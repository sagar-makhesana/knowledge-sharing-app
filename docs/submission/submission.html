The problem

The answer usually exists. Finding it is the hard part.

Altegra consultants work on the same platforms at many customers: Aras Innovator, Teamcenter, SQL Server, IIS and their integrations. The same problems keep coming back: a Method that breaks after an upgrade, an app pool that recycles mid-day, a collation conflict after a restore.

  • The fix lives in someone’s head, an old Teams chat or a customer wiki, none of which can be searched by symptom.
  • So consultants interrupt colleagues or solve it again from scratch, while the customer waits.
  • Writing documentation feels like admin, so it rarely happens. Knowledge leaves when people change projects.
Our answer

One place, built around two moments of the day

“I’m stuck.” Type the error or symptom and get ranked answers with the matching words highlighted, even with a typo.

“I just fixed it.” Share it in a few minutes with a guided template, Markdown and code blocks, without an account.

The loop between them: a search that finds nothing offers Submit this knowledge, with the title pre-filled, so every gap becomes the next entry.

Example: Priya’s reports fail after a database restore. She types colation conflict, with a typo, and the first result has the exact error, root cause and T-SQL fix a colleague wrote months ago. She is done in minutes instead of searching all morning.

Innovation

What’s different about it

Search tuned for technical text

  • Title and tags weigh more than body text.
  • Prefix matching while typing (recycl finds “recycling”).
  • Typo tolerance only on longer words, so lock doesn’t match “look”.
  • Filler words are ignored, so “how to fix the collation” works.
  • All words must match. If nothing does, partial matches are shown with a notice.
  • The exact matched words are highlighted, including in tags.

Designed to be used, not just filled in

  • The knowledge loop: failed searches turn into pre-filled submissions, so the knowledge base grows where people need it.
  • Zero-friction sharing: no account, a guided template, and tag suggestions that keep the vocabulary consistent.
  • Shareable searches: every query, filter and sort is a link to paste into Teams.
  • Always current, no search server: the index rebuilds itself when the data changes, even across serverless instances.
Technical execution

Built properly, deployed and running

ArchitectureNext.js 16 on Vercel: server-rendered pages, Server Actions for saving, and a MiniSearch index, backed by Supabase Postgres. All code uses one KnowledgeRepository interface, so Supabase and an offline JSON file are interchangeable. UUIDs and ISO timestamps keep data portable.
CorrectnessStrict TypeScript. One Zod schema validates in the browser and again on the server. 50 automated tests cover storage, search ranking and server actions.
SecurityThe database key is only used on the server, Row Level Security blocks direct access, and user Markdown is rendered without raw HTML.
AccessibilityLabelled inputs, keyboard use (/ to search), visible focus, announced result counts, and responsive layouts.
StackNext.js 16, React 19, TypeScript, Tailwind CSS 4, shadcn/ui, Zod 4, MiniSearch, Supabase, Vitest.
